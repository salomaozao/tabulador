Protótipo — topo enxuto e leitura cronológica do projeto

Mockup estático do Tabulador com as mudanças pedidas: o topo fica só com o essencial, a seleção de projeto vira um menu no próprio título, e o andamento passa a ser lido em % de perguntas com um gráfico de progressão. Nada aqui é o app real — é para bater o olho e dizer o que fica.

1 · Topo enxuto — o que sai e para onde vai

🧪
Modo teste → para dentro de ⚙ Configurar IA (e a faixa amarela continua aparecendo no topo só enquanto ele estiver ligado, porque é estado, não botão).
↻
Recarregar planilha → para dentro de 🛠 Gerenciar projeto: é ação rara e é lá que vivem as ações de base.
▾
Seletor de projeto + + Novo projeto → viram um menu no título do projeto. O topo deixa de ter um <select> anônimo no meio da barra.

6 · Como cada número é calculado

①
% das perguntas revisadas = perguntas com n_revisadas = n_codificadas (revisão concluída) ÷ total de perguntas abertas do projeto. Denominador fixo — não muda quando a base cresce.
②
Contador sticky = respostas conferidas ÷ respostas únicas daquela pergunta. Vale a leitura "já olhei X de Y respostas"; a barra é essa fração.
③
Gráfico — as duas séries saem de dados que já existem: revisadas de validado_em/revisado_em item a item no codificacao.json; classificadas dos timestamps de output/llm_log/ (as chamadas code_*), que a aba Consumo já lê. Cada ponto é cumulativo até o fim do dia, e a pergunta entra na série no dia em que a última resposta dela atinge aquele estado. É reconstruível do histórico atual — sem precisar começar a medir do zero.
